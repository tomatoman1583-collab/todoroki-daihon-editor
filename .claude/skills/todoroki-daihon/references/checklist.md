# 納品前セルフチェックリスト

台本（または修正箇所）を納品する前に、上から全項目を確認する。
1つでもNGなら直してから出す。

## A. 中身（クライアント要望）

各車について：

- [ ] **要素1**：メーカーが誰に売ろうとしたかが書かれている
- [ ] **要素2**：その客層が実際に求めたもの（＝ズレ）が書かれている
- [ ] **要素3**：競合車を**具体名**で挙げ、何が弱かったか書かれている
- [ ] **要素4**：スペック・設計を「だから売れ行きにこう響いた」と因果でつないでいる
- [ ] **要素5**：消えた最大の理由を1つ言い切っている
- [ ] 基本情報（発売年・価格・スペック）だけで字数を埋めていない
- [ ] **価格は1台につき原則2つまで**（発売時の最安＋今の最上級）。グレード表・地域差・年ごとの小刻みは削った
- [ ] スペックの数値は「結果に効いた1〜2個」だけで、必ず分析に接続している（詳細は analysis-framework.md「数字の出し方」）
- [ ] 冒頭でテーマの分析軸（問い）を宣言し、締めで回収している
- [ ] 「調べて初めて分かる背景／納得できる分析」が入っている（言い換えだけになっていない）

## B. 比喩

- [ ] 比喩は1台につき0〜1回に収まっている
- [ ] 比喩の直後に現実の理由・分析へ戻している
- [ ] 比喩で文を終わらせていない（意味を具体語で説明している）
- [ ] 動画全体で比喩が「コント」に見えるほど多くない

## C. 構成・締めの多様性

- [ ] 冒頭が「発売→特徴→売れない→生産終了→不遇の名車」のテンプレになっていない
- [ ] その車で最も興味を引く事実から入っている
- [ ] 締めが「不遇の名車でした」「時代に合わなかった」の使い回しになっていない
- [ ] 締めが車ごとに異なり、要素5と一致している
- [ ] 隣り合う車で冒頭・締めが被っていない

## D. 佃さんスタイル

- [ ] `references/tsukuda-style.md` の口調・言い回し・分析の型に寄せている

## E. フォーマット（エディタの機械チェック）

- [ ] 全行が26字以内（26字超過 = 0）
- [ ] 句点「。」を使っていない（句点 = 0）
- [ ] 1行＝ひと息で読める1つの意味になっている
- [ ] 空行で話題のまとまりが区切られている
- [ ] `references/format.md` の簡易スクリプト or エディタで超過0・句点0を確認した

## F. 事実確認

- [ ] 数値・競合・時系列など、事実部分の裏取りができている（不確かな箇所はユーザーに確認済み）
