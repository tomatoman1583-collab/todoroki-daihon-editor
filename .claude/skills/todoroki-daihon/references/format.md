# 納品フォーマット仕様と検証手順

台本は `index.html`（轟 台本エディタ）で読み込まれ、機械的にチェックされる。
エディタの実装（`render()`）が見ているのは次のとおり。

## ルール

| ルール | エディタの挙動 | 対応 |
|---|---|---|
| 1行26字以内 | `len(t) > 26` の行を**赤**表示・「26字超過」カウント | 意味の切れ目で改行し、各行26字以内に収める |
| 句点「。」禁止 | `。` を含む行を**黄**表示・「句点」カウント | 文末の句点を打たない。区切りは改行で表す |
| 1行＝1読み上げ | 行をクリックするとその行から読み上げ | 1行に1つの意味・ひと息で読める長さ |
| 空行でブロック区切り | 空行は `blank` として表示 | 話題のまとまりごとに空行を入れる |

補足：
- 文字数カウントは `[...s.trim()].length`（コードポイント単位）。全角も半角も1文字＝1。前後の空白は無視される。
- 読点「、」は制限なし。長い行は「、」の位置で改行するのが自然。
- 「26字」はあくまで上限。読みやすさ優先で、多くの行はもっと短くてよい。

## 番号体系（納品スプレッドシートの形式・実物台本から確認済み）

台本は最終的にスプレッドシート（No.列＋セリフ列）に載る。テキストで書く場合も同じ構造で：

- **1つの意味単位（ひと息のセンテンス）＝1つのNo.**（001, 002, 003…）
- 26字に収まらない意味単位は **NNN-01 / NNN-02 の2行に分割**する（3行分割はしない。
  2行で収まらないなら文を2つの意味単位に割る）
- 意味単位の間には**空行**を入れる
- **車名は見出しとして独立した1行**にする（例：「日産・ピノ」）
- 実測の目安：平均17〜19字/行。26字は上限であり、常に詰める必要はない

## 書き方のコツ

- 一文が長くなったら、主語・条件・結論で改行して複数行に割る。
- 数値（300万円、1530mm、280馬力など）は行頭 or 行末に置くと読み上げが安定する。
- 体言止め・言い切りを活用して句点なしでもリズムを作る。

## 納品前の機械チェック手順

1. 台本テキストを `index.html` をブラウザで開いて貼り付ける（またはファイルを「台本を開く」で読み込む）。
2. 上部の指標を確認する：
   - **26字超過 = 0**（赤い行がない）
   - **句点 = 0**（黄色い行がない）
3. 赤・黄が残っていれば全て解消してから納品する。

### コマンドラインで素早く自己チェックしたい場合

エディタと同じ条件で、超過行と句点行だけ洗い出す簡易スクリプト：

```bash
python3 - "$FILE" <<'PY'
import sys
for i, line in enumerate(open(sys.argv[1], encoding='utf-8'), 1):
    t = line.strip()
    n = len(t)                       # コードポイント数＝エディタのlen()と同じ
    flags = []
    if n > 26: flags.append(f'26字超過({n})')
    if '。' in t: flags.append('句点')
    if flags and t:
        print(f'L{i}: {" / ".join(flags)} : {t}')
PY
```

出力が空なら機械チェックはパス。

## 表記ルール（恒久・クライアント指定）

- **単独で「くるま」を指す「車」は「おクルマ」と書く。**
  例：「高くなっただけの車は」→「高くなっただけのおクルマは」、「小さな車が」→「小さなおクルマが」。
- **「○○車」という複合語（車が「しゃ」と読まれる／固定語になっている部分）は変更しない。**
  例：大衆車・国産車・軽自動車・新車・車名・車重・全車・外車・名車・特別仕様車・車両・駐車場・両車 等はそのまま。
- 判断に迷う語（例：「両車」のような複合カウント語）は複合語側（変更しない）に倒す。
- 変換後も26字ルールに注意（「お」「クルマ」で+1〜+3字増えるため、境界付近の行は要再確認）。

## 冒頭の扱い（恒久ルール）

- 固定の挨拶文（「皆さんどうも轟です」等）は**台本に含めない**。挨拶はクライアント側で別途挿入する。
- 台本は**テーマ発表（「さあ今回は」または「今回は」）から開始**する。
- 車の見出し（①②③…）を冒頭の一番先頭（テーマ発表より前）に置く指示が来ることがある。
  その場合、元の位置（各車紹介の直前）の見出しは重複するため削除し、先頭の1箇所だけにする。

## 納品プレビューの見せ方（エディタ画面として出す）

ユーザーに読み味を確認してもらうときは、`index.html` エディタの見た目を再現した
HTMLを **Artifact として publish** する（サイドパネルに即開くので「パッと出る」）。
SendUserFile の添付だと開くのに一手間かかるため、プレビューは Artifact を使う。

### 編集可能版にする（推奨・デフォルト）

読むだけでなく直接手を入れたい、という要望が出やすいので、最初から**編集可能な単一ペイン**で作る。

- **プレビューとテキストエリアを分けない。** 1つの `<textarea>` の左に文字数ガター（行ごとの文字数、
  26字超過は赤・句点は黄の背景）を重ね、`input` イベントで再計算する。
- **ガターの高さは textarea と同じ絶対px（`line-height` に固定px値を使う）で統一する。**
  異なるfont-sizeや`calc()`頼みにすると、行数が増えるほど1px未満のズレが蓄積し、
  下の方の行でガターと本文がズレる／表示が「途中で終わったように見える」バグになる（実際に発生した）。
  スクロール同期は `transform: translateY()` ではなく、**ガター側の `scrollTop` を本文の `scrollTop` に
  直接代入する**方式にする（transformで枠ごと動かすと枠が画面外に飛び出し得る）。
- **読み上げも実装する。** `index.html` と同じ方式（単一の長い `SpeechSynthesisUtterance` を
  `onboundary` イベントで追跡し、10秒おきに pause/resume するキープアライブでChromeの長文停止バグを回避、
  ローカル音声を優先選択）。ガターの数字をクリックでその行から再生。
- **ボタン構成**：💾 保存（`showSaveFilePicker` があれば同一ファイルへ上書き、なければダウンロードにフォールバック）／
  📋 コピー（クリップボードへ。保存が失敗したときの確実な代替手段。**必ず両方入れる**）／
  CSVで書き出し（No.・セリフの2列、納品シート貼り付け用）／元に戻す。
- **検証は必ずヘッドレスブラウザで実測する。** CSSの計算だけで「揃っているはず」と判断しない。
  Playwright等でスクロール位置を変えてスクリーンショットを撮り、実際に数字と本文が揃っているか
  目視確認する（このスキルの制作中、計算上は0.001px差という数値だけを見て「合格」と誤報告した失敗があった。
  スクリーンショットを見て初めて、レイヤーごと画面外にずれている実際の不具合に気づいた）。

### 保存の限界（ユーザーに伝えるべきこと）

- `showSaveFilePicker` は**タブがリロードされるたびにファイルの紐付け（権限）が失われる**。
  Artifactを再publishしてユーザーがページを再読み込みすると、次回の保存は再びファイル選択
  ダイアログが必要になる（無言で上書きされ続けるわけではない）。
- Artifact上の保存は、あくまで**ブラウザのタブの中で完結する一時的な機能**であり、
  クライアントの実際のローカル運用（本物の `index.html` エディタでの保存）とは別物。
  「今後は本物のエディタで保存、Claude側は分析・編集してテキストを返すだけ」という
  役割分担を最初から明示しておくと事故が起きにくい。
- 編集内容の受け渡しに失敗した形跡があれば、**ユーザーに現在の編集エリアの全文を
  コピペしてもらい、それを新しい正本としてスクリプト側に取り込む**（記憶や推測で復元しない）。
  取り込んだら `difflib` 等で差分を機械的に出し、意図した変更点だけが入っているか確認してから反映する。

- エディタの見た目に合わせる（ヘッダーに 総字数／26字超過／句点、右端に文字数バッジ、
  26字超過は赤・句点は黄）。トークンは `index.html` の配色を流用し、ライト／ダーク両対応にする。
- 車名（①〜⑥）の行は区切りとして少し強調してよい（実エディタにない補助だが可読性のため）。
- 同じ台本の **CSV（No.・セリフの2列）** も併せて渡す（納品シート貼り付け用）。
