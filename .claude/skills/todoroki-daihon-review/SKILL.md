# 轟き台本 差分監査スキル

`todoroki-daihon` スキルで書いた・直した台本が、実際にクライアント要望を満たしているかを、
**修正前と修正後を並べて**検証する。「直したつもり」を「直っている」に変える最終チェック。

このスキルは執筆しない。**採点する。** 未達成が見つかったら `todoroki-daihon` の型に戻って直し、
直したら再度この監査を回す（**書く → 測る → 直す** のループ、直るまで終わらない）。

## 監査の基本方針

- 修正前・修正後の**両方のテキストを実際に読む**。要約や記憶だけで判定しない。
- 各項目は「Before：〇〇だった」「After：〇〇になった」を**引用付き**で記録する。
  「良くなった」で終わらせず、何がどう変わったかを本文の言葉で示す。
- 満たしていない項目は隠さず「未達成」と明示する。直せるものはその場で直す。
- ルールの正本は `../todoroki-daihon/SKILL.md` と `../todoroki-daihon/references/checklist.md`。
  このスキルはそれをBefore/After比較の形に展開したもの。

## 監査の手順

### 1. 車（ブロック）ごとの対応表を作る
修正前・修正後を車ごとに並べる。車の数・順番が変わっていないかもここで確認。

### 2. 車ごとに、内容面をBefore/Afterで判定
不遇系なら5要素、他テーマなら該当の分析軸（`analysis-framework.md`「テーマ別の分析軸」）を使う：

| 項目 | Before（引用） | After（引用） | 判定 |
|---|---|---|---|
| 客層・狙い→現実とのズレ | | | 済/未 |
| 競合の具体名 | | | 済/未 |
| 数値→結果の因果 | | | 済/未 |
| 結論の言い切り（締め） | | | 済/未 |

「Beforeは事実の羅列だったが、Afterで◯◯という原因まで踏み込んだ」の形で書く。

### 3. 台本全体レベルの項目をチェック

- **比喩の総数**：Before何回／After何回。台本全体で1〜2回か。1台に2つ以上残っていないか。
- **冒頭の多様性**：車ごとの入り方が同じテンプレになっていないか（Before/Afterとも確認。
  Afterで新たなテンプレ化が生まれていないかも見る）。
- **締めの多様性**：「不遇の名車でした」等の使い回しがAfterに残っていないか。
- **数字の圧縮**：グレード表・地域差・年次改定など一次情報の羅列がAfterで削られているか
  （`analysis-framework.md`「数字の出し方」）。1台につき原則2つ（発売時最安＋最上級）に収まっているか。
- **佃さんスタイル**：テーマ論の宣言と締めでの回収があるか。一行サマリ（対句・逆説の言い切り）が各車にあるか。
- **冒頭の扱い**：固定の挨拶文（「皆さんどうも轟です」等）が入っていないか（クライアントが自分で挿れる前提）。
  台本はテーマ発表（「さあ今回は」）から始まっているか。
- **フォーマット**：26字超過0・句点0（`format.md` の簡易スクリプトで機械チェック）。No.採番が正しいか。

### 4. その回の個別指示の反映確認

その依頼で追加された個別指示（例：「比喩は2回まで」「テーマ発表を40〜50字削る」など）は、
上のチェックリストになくても**必ず監査項目に追加**し、Before/Afterで満たされているか確認する。
個別指示は正本チェックリストより優先する。

### 5. 総合判定

- 全項目「済」→ **合格。納品可。**
- 「未」が残る → `todoroki-daihon` の型に沿ってその場で直し、直した箇所だけ再監査する。
- 監査結果は表で提示する。総当たりで全項目を並べる必要はなく、
  **意味のある変化があった項目・未達成の項目**を優先して示す。

## 出力フォーマット（ユーザーへの報告）

1. **全体サマリ**（3〜5行）：主要な変化と、要望を満たせているかを一言で。
2. **車ごと／項目ごとの表**（Before引用・After引用・判定）。
3. **未達成があれば**：どう直したか（Before → 再修正後）を示す。
4. **最終判定**：合格、または残っている要修正点。

---

書いて終わりにしない。**書く → 測る → 直す** を1セットとして毎回回す。
